# 淺色精品科技風格設計

## 背景

目前第二頁「進階微調」的風格庫多數使用深藍、黑色或高對比底色。2026-08-20 已用現有 `user_instruction` 機制完成一次付費控制測試，證明 GPT 圖片模型能穩定生成高明度的銀藍、珍珠白與香檳金視覺。

本功能把該次驗證成功的配色與材質語言保存為第二頁可重複選用的風格，不改變第一頁 AI 自動消化的預設行為。

## 使用者決策

- 風格需出現在全部四種圖表類型：
  - 資料圖表
  - 情境示意圖
  - 地圖／位置
  - 3D示意／流程
- 第二頁分類名稱：`淺色風格`
- 風格選項名稱：`銀藍香檳金`
- 同時修正編輯版消化的深色錨定：跟記者版對標，不提供任何範例配色，讓消化 agent 依新聞內容自行決定最合適的配色。
- 本次不改記者版消化 prompt，也不進行付費生圖。

## 資料設計

在 `app.js` 新增單一共用常數 `LIGHT_LUXURY_TECH_STYLE`，四種類型皆引用同一物件，避免日後四份英文 Prompt 漂移。

風格 Prompt 固定包含：

- 高明度、低至中飽和
- 霧藍灰、銀藍、珍珠白主背景：`#B4C7D5`、`#D1DADB`、`#A3B8CA`
- 半透明冰藍、銀白與冷灰資訊卡
- 香檳金、柔金、少量古銅金重點：`#CBA352`、`#D6CDAF`、`#966F30`
- 深鋼灰或深藍灰文字
- 禁止大面積深藍／黑底、霓虹色及高飽和科技藍
- 玻璃、拉絲金屬、細線網格與柔和高鍵棚燈
- 漲跌數據仍遵守臺灣慣例：漲／增加用紅色，跌／減少用綠色；紅綠不可作無關裝飾

四個 `styles` 物件各新增：

```javascript
'淺色風格': [LIGHT_LUXURY_TECH_STYLE]
```

既有 `renderParents()`、`renderTags()`、`updateSpecificField()` 已能直接處理這種資料，不新增 UI 分支或狀態。

## 編輯版消化去除配色錨定

`main.py` 的 `EDITOR_SYSTEM_PROMPT_TEMPLATE` 目前在 style 規則中列出「深藍色科技感、紅白色警戒感」兩個範例；這是全庫主流程唯一明列的配色範例，會在模型既有的深色新聞 CG 先驗上再增加錨定。

本次把該行改為不含任何色名或配色例子，只保留任務與輸出語言：

```text
2. "style": 根據新聞調性（財經、災難、溫馨、政治）自行選擇最合適的主色調與畫面風格，written in professional English.
```

這與記者版 `SYSTEM_PROMPT_TEMPLATE` 的中性原則對標：要求模型選擇專業且適合題材的風格，但不替模型預先指定深色或淺色。

預期效果是移除人為的深色 few-shot 錨定，不保證短期樣本會平均分配深淺色；模型本身的新聞 CG 先驗仍可能偏深。第二頁新增的「銀藍香檳金」則提供需要確定淺色結果時的手動選項。

## 編輯版薄邊安全框改為 4%

目前 `safe_area_spec.py` 的實際薄邊規格是四邊 3%，但 `app.js` 仍誤顯示為 2%。使用者已確認兩者都要改成 4%，不是只修正文案。

1920×1080 基準畫布的目標幾何：

- 左右留白：`round(1920 × 4%) = 77px`
- 上下留白：`round(1080 × 4%) = 43px`
- 內容矩形：`X=77 / Y=43 / W=1766 / H=994`
- 內容比例約 1.7767，與 16:9 幾乎相同，沿用 FIT 等比例置入即可零裁切、零拉伸
- 此薄邊是編輯自訂框，不改記者官方安全框，也不改編輯對位框
- 投影是否停用繼續交由既有 `_shadow_fits()` 通則判斷，不為 4% 新增硬編碼分支

前端安全框徽章同步顯示「編輯安全框（四邊 4%）1920×1080」。

## UI 行為

使用者在第二頁選擇任一圖表類型後：

1. 開啟「風格包／子風格」。
2. 點選父分類「淺色風格」。
3. 點選「銀藍香檳金」。
4. 英文風格 Prompt 寫入 `field-style`。
5. Final Prompt Output 立即同步更新。

切換四種圖表類型時，每一類都能找到相同分類與選項。各類型的選取狀態仍依現有 `selectedByType` 分開保存，不互相污染。
