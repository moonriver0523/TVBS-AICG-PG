# 2026-09-05 消化階段吐賭博垃圾與無限空白：gpt-5.6-terra 的頻道洩漏

## 使用者看到什麼

網頁版按「AI 消化」之後，時而卡住約 90 秒後跳「AI 服務連線失敗」，時而拿到一份
看起來正常、實際上尾巴接了亂碼的消化結果，直接送去生圖就把亂碼畫進成品。

Cloud Run 日誌（2026-09-05 UTC 06:17–06:31，臺灣時間 14:17–14:31）：

```
06:18  POST /api/generate → 502
06:21  attempt 1/5 parse failed (finish_reason=length)：line 2378 column 11 (char 7871)
06:22  attempt 2~5 全部 quality check failed（西里爾／亞美尼亞／馬拉雅拉姆雜字）
06:22  POST /api/generate → 502
06:31  attempt 1/5 quality check failed：variable 拉丁字母比例 60% 過高
```

同時段 `/api/images/generate` 零次呼叫、GCS 歷史檔最後一筆停在 01:38——
**這一輪根本沒走到生圖**，前端顯示的是 app.js 的「AI 服務連線失敗」。

## 根因

`openai/gpt-5.6-terra`（經 OpenRouter，provider 回報 `OpenAI`）會把**內部頻道路由語法
洩漏進可見內容**，並在洩漏處接上簡體賭博廣告語料。本機重現抓到的完整原始輸出：

```
<蓋章>提醒民眾避開低窪路段}} դժassistant to=system.summary  天天中彩票不json: {
```

```
...numerusformassistant to=assistant.final  天天彩票中奖json? It persistently emits
blank because I never add content. Add content:ьҭаassistant to=assistant.final
天天中彩票怎么买json? Damn. Let's terminate all analysis with actual final designated
from editor.ныҳәаassistant to=assistant.final  北京赛车前json? This token waste is fatal.
```

模型把 `assistant to=assistant.final` 這種角色／頻道標記當成一般文字吐出來，中間
夾雜西里爾、亞美尼亞、馬拉雅拉姆、泰文與「天天中彩票」「北京赛车」「彩神争霸破解」
等賭博站關鍵字，並一邊自言自語說自己輸出是空的。這是模型／provider 側的
harmony 模板缺陷，不是我們的 prompt 寫壞。

### 為什麼 strict JSON schema 擋不住

`digest_completion` 已經用 `response_format: json_schema, strict: true`。但受限解碼
只保證**文法合法**，不保證有內容：

- 賭博垃圾與頻道標記出現在 `"variable"` 字串內部——字串裡什麼字元都合法。
- 模型崩掉之後改吐純空白。JSON 文法允許 token 之間有任意多空白，於是它一路
  填空白到 `max_tokens` 天花板。實測一筆：12,391 字元裡 **84.4% 是空白**，
  2,736 行，其中一段連續 9,089 個空白字元，最後 `finish_reason=length`。

`reasoning_tokens` 只有 99——**不是推理 token 吃掉預算**，是解碼卡死。

## 量化

本機重現，同一份 system prompt（`自動判斷`／記者／standard／dark／stamp on），
三則新聞各跑 3 次：

| 模型 | 污染筆數 | 硬失敗（length） | 正常輸出 token |
|---|---|---|---|
| `openai/gpt-5.6-terra` | **7 / 9** | 2 / 9 | 469–1,152 |
| `anthropic/claude-sonnet-5` | **0 / 6** | 0 / 6 | 1,312–2,324 |

污染判定：輸出含 `assistant to=` / `to=final` / `numerusform` / 賭博站關鍵字。

失敗會跟著題材黏著：隧道那題 3 次錯 2 次，基隆與維基那題各自穩定。因此正式站
才會出現「5 次重試全滅」——重試對會觸發的題材沒有用，只是把 5 × 60 秒燒滿，
撞破 Cloud Run 的 300 秒上限變成 502。

## 兩個被推翻的舊結論

**一、「只有地圖類會這樣」不成立。** 網頁預設是「自動判斷」，而
`digest_token_budget()` 把 `自動判斷` 與 `地圖／位置` 並列給 `MAP_DIGEST_MAX_TOKENS`
（6000），`build_digest_instructions()` 也對兩者同樣注入 7,693 字元的
`MAP_ACCURACY_RULES`。結果是**每一次網頁預設消化都帶著完整地圖規則**，
system prompt 達 23,795 字元（明確指定「資料圖表」只有 14,860）。
2026-09-04 的回滾對照只測了明確地圖類，沒有涵蓋這條 auto 路徑。

**二、「地圖類要寫的東西多，所以預算要 6000」很可能是誤診。** 實測正常完成的輸出
只用 469–1,152 token（ratio 0.09–0.11）；14 天日誌裡所有 `finish=stop` 的最大值是
1,536，超過 2,300 的那幾筆（3,579／4,837／5,157／5,226／5,559）全是脫軌後
才停下來的。2026-07-31 記下的「1500 會截斷、3000 還截斷」很可能就是同一個脫軌
bug，把預算加大只是讓每次脫軌多燒 4 倍 token 與時間。

## 品質閘漏掉的那一種

最危險的不是 502，是**通過檢查的那些**。terra 這筆：

```
<蓋章>提醒民眾避開低窪路段}} դժassistant to=system.summary  天天中彩票不json: {
```

- 異常字元只有 `դժ` 兩個，未達 `DIGEST_MAX_STRAY_CHARS = 3`；
- 其餘是 CJK 與 ASCII，拉丁字母比例遠低於 `DIGEST_MAX_LATIN_RATIO = 0.55`。

於是 `digest_quality_problem()` 判定合格，這段文字會原樣進入最終 prompt 送去生圖。
真正的指紋是 `assistant to=`、`to=final`、`numerusform` 這些**頻道標記**與賭博站
關鍵字，字元集檢查看不到它們。

## 重現方式

`scratchpad/digest_probe.py`：直接 import `main`，用與 `/api/generate` 相同的
`build_digest_instructions()` 與 `digest_completion()` 呼叫，記錄
`finish_reason`、`completion_tokens`、`reasoning_tokens`、provider、輸出字元數、
行數、空白比例與完整原始輸出。線上日誌只留 `raw_content[:800]`，看不到退化的尾巴，
一定要在本機抓完整輸出才看得到病因。
