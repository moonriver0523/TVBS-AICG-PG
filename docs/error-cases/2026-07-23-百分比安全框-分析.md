## 四輪累計結論

1. **穩定戰果**：「嚴禁畫出數字／%字元」防護句有效——數字入圖 0/18（對照：% 舊版與像素版都大量中招）。approximately＋範圍寫法可能也有貢獻。
2. **括號入圖已根治（R3）**：根因是舊規則「`[text]` or `<text>` → 去括號後高亮該文字」把行類型標籤與強調標記混為一談——模型渲染「內文小標」其實是**照規則做**。語義三分＋規則區清光字面括號 token 後 0/4。教訓：**先查是不是規則自己教出來的錯，再加防護句**。
3. **底部壓帶是語意理解問題，不是力度問題**：帶區加深（18–22%→22–26%）＋「視同裁掉」框架後仍 3/4 違規，GPT 甚至拖更低（~90–93%）。GEMINI-1 更把「底部保留帶」理解成「放總結橫條的地方」——可見色帶＋帶內文字雙重違規。模型對「留白」的先驗是「填東西」，prompt 壓不過。
4. **prompt 調參天花板確認**：空間精度類問題（壓帶／貼頂／貼邊）修辭再強都收斂不到廣播級一致性；語義類問題（數字入圖／括號入圖）則可根治。這條分界線本身就是本輪實驗最大產出。
5. **% 版仍優於其他路線**：純文字版（留邊不一致）＜ % 版 ＜ 理論上的混合版型。像素版全滅墊底。佐證混合版型（`docs/hybrid-rendering-proposal.md`）為正解：版面與文字由 APP 控制，這整類問題直接消失。

## 狀態

R3（`0885610`）後：語義類問題全數根治（數字 0/18、括號 0/4），空間類問題（底部壓帶 3/4、GPT 貼頂貼邊）確認為 prompt 調參治不了的殘留。依「調到堪用即收」共識，**% 版已達 prompt-only 天花板，建議收手**，資源轉向混合版型決策。
