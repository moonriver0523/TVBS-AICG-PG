# 2026-08-05 多人肖像：fail-safe 整個沒生效，兩張假臉掛真名姓名條

> 使用者實際回報的線上事故。成品：`2026-08-05-多人肖像-兩張假臉掛真名姓名條.png`

## 一、發生什麼事

使用者在 LINE 送出「請做一個圖, 鄭明典/ 吳軒彤的人頭+ 今日天氣」，
系統回傳一張**兩格並排肖像**的天氣圖，兩張臉都不是本人，而且各自掛著
「氣象專家 鄭明典」「氣象主播 吳軒彤」的姓名條。

`request_id=e2ad41df0079`｜11:56:29｜`openai/gpt-image-2`｜`prompt_version=v4-2026-08-01`

| 欄位 | 值 |
|---|---|
| `portrait_subject` | **`'鄭明典'`（只有一個人）** |
| `portrait_mode` | `reference` |
| 附上的參考照 | 鄭明典的維基條目 |
| STRUCTURE | 要求兩個並排肖像框（左：氣象專家／右：氣象主播） |

另查證：**吳軒彤在維基查無照片**，鄭明典查得到。

## 二、根因鏈

1. `portrait_subject` 是**單一字串**（schema 也是 `{"type":"string"}`），
   整個設計假設「一張圖只有一位具名真人」。規則第 5 條寫的也是
   「ONE specific named real person」——**消化端是照規則走的，缺的是多人情境**。
2. 使用者要兩個人 → 只填得下鄭明典，**吳軒彤從頭到尾沒進入肖像流程**。
3. 後端只附一張照片，注入的規則是單數「A reference photograph of the named real
   person is attached」，**沒有指明是給哪一格**。
4. 模型手上一張照片、兩個框要填 → 兩張臉都自己畫，還都掛上真名。

## 三、真正的教訓：fail-safe 只看單一狀態就會失效

「查不到照片就不畫臉」的保護是綁在單一 `portrait_mode` 上的。
因為鄭明典查得到、mode 判成 `reference`，**「不得繪製臉孔」那段規則根本沒被注入**，
第二格等於完全放行。

結果是最壞的組合：**掛著真人姓名條的憑空捏造臉孔**——比畫得醜嚴重得多，
牽涉肖像權與觀眾誤認。圖上雖有「示意圖」三字，但在右下角極不顯眼。

這是先前 TODO 記的「維基首圖未經身分驗證」的升級版：當時只想到「會找錯人」，
沒想到「多人時保護會整個失效」。

## 四、處置（已實作）

1. **`portrait_subject`（字串）→ `portrait_subjects`（陣列）**，規則第 5 條改成
   「列出畫面上**每一位**具名真人，只列第一個是缺陷」。單一欄位裝不下第二個人，
   這是事故的結構性起點。
2. **兩人以上一律不畫臉**：`resolve_portrait` 在名單長度 > 1 時直接回 `no_reference`，
   而且**不查照片**（查到了也不能用）。參考圖通道一次只對應得了一個人。
3. **`PORTRAIT_NO_REFERENCE_RULES` 改為複數語意**，明文涵蓋「兩格並排」的情況，
   並加上「姓名條可以留，但必須配在沒有臉的人形旁邊，絕不可配在捏造的臉旁」。
4. `clean_portrait_subjects()` 洗掉 null／字串／重複，避免同一人被列兩次而誤判成多人。
5. `PROMPT_VERSION` bump 至 `v5-2026-08-05`。

**用原句實跑驗證**（純消化、未生圖）：
```
portrait_subjects = ['鄭明典', '吳軒彤']
[portrait] 畫面有 2 位具名真人（鄭明典、吳軒彤），一律不生成臉孔
portrait_mode     = no_reference
注入的肖像區塊    = 不畫臉(NO REFERENCE)
```

## 五、還沒解決

- **真正的多人肖像支援**：要能逐格對應各自的參考圖（OpenAI 端最多收 16 張，
  但「哪張對應哪一格」還沒實測過）。在那之前，多人一律不畫臉是刻意的取捨。
- **人物身分驗證**：維基 `pageimages` 只抓條目首圖，仍可能不是本人。
- 「示意圖」標籤的顯著度：目前可能被放到角落，需要規則約束位置與大小。
