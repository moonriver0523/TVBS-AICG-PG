# 台灣地圖行政區界一律畫錯：是模型缺陷，也是管線漏洞（2026-09-10）

## 使用者回報

> 我發現他畫台灣地圖的時候還是會有錯誤，行政區的邊界完全是錯的，查一下這個是什麼造成的，
> 模型本來的缺陷還是消化端的問題

問的是歸因。答案是**兩者都有，而且管線這一側是可修的那一半**。

## 案例

2026-09-10 記者版 CG 創意階梯實拍，同一則高溫熱傷害新聞跑 0–4 級：

| 檔案 | request_id | 症狀 |
|---|---|---|
| `20260910b-sunburst創意1.png` | `4bbe425190cd` | 左側臺灣地圖，縣市界與實際不符 |
| `20260910b-sunburst創意2.png` | `db8165dcc7ab` | 置中衛星風臺灣地圖，縣市界與實際不符 |

兩則的消化輸出 `chart_type` 都是 **`資料圖表`**，不是地圖類。structure 卻分別寫著：

- 創意 1：`Use one dominant central heat-alert composition combining an accurate Taiwan silhouette with highlighted northern basin and central regions…`
- 創意 2：`Use one dominant, geographically accurate Taiwan map through the central area, with the northern basin area and Taichung area highlighted…`

也就是：**消化端點名要「地理準確的臺灣地圖」，還要求把特定縣市反白**——而整條管線此時完全沒有任何地理資料可以給生圖模型。

## 三層歸因

### 第一層：管線漏洞（可修，且是主因）

`build_digest_instructions`（`main.py`）目前的注入條件是：

```python
if type_label in (MAP_TYPE_LABEL, AUTO_TYPE_LABEL):
    instructions += MAP_ACCURACY_RULES
elif map_scope_guard:                    # 只有兩段式分類成非地圖時才 True
    instructions += MAP_SCOPE_GUARD_RULES
```

而 `DIGEST_TWO_STAGE` 預設是關的（`main.py`，旗標預設關的理由見該處註解），所以 `map_scope_guard`
永遠是 False。本案 `type_label="資訊卡"`（使用者明確指定的非地圖類型）：

- 不符合第一個條件 → **`MAP_ACCURACY_RULES` 沒注入**
- `map_scope_guard` 為 False → **`MAP_SCOPE_GUARD_RULES` 也沒注入**

結果是這條路徑上**一條地理約束都沒有**。`MAP_ACCURACY_RULES` 第 4 條本來就是為了擋這件事寫的
（「沒有座標就不准用 accurate／geographic 這種字眼，改走示意 fallback」），開頭句也刻意寫成
「就算你把 chart_type 報成 資料圖表 也照樣綁住你」——但它根本沒被送進 prompt。

**明確指定非地圖類型 ≠ 這張圖不會畫地圖。** 這正是漏掉的假設。

### 第二層：底圖機制構不到（設計上的邊界，不是 bug）

`resolve_map_points()` 第一行就是 `if chart_type != MAP_TYPE_LABEL: return []`。
`chart_type` 是 `資料圖表`，所以 OSM 真實底圖（`map_lookup.render_basemap`）不會產生、
不會附上。附帶一提，就算是地圖類，`attach_map_basemap` 還要求
`supports_multiple_reference_images()`——那條只有 OpenRouter 走得通，原生 OpenAI 路徑一律略過。

### 第三層：模型缺陷（不可修，只能繞開）

即使前兩層都補上，**現有的 OSM 底圖機制也修不好行政區界**：它畫的是「圖磚＋標點」，
給的是點位，不是縣市界向量。而生圖模型憑記憶畫國界／縣市界一律不準——這與
`docs/error-cases/2026-07-23-沖之鳥島-位置偏移-分析.md`（島嶼位置）、
2026-09-04 基隆案例（「西定路」偏 1.47 公里）是同一個病：**空間精準的事情不能交給模型**。

## 結論

- **prompt 修得掉的**：不該出現「地理準確的臺灣地圖」這種要求。做法是讓非地圖類型也拿到守門條文。
- **prompt 修不掉的**：行政區界本身。要真的畫對，必須比照 `safe_frame.py`／`compose.py`
  的原則，由程式用真實圖資（縣市界 GeoJSON）畫成圖層，模型只負責美術。

## 已做的處置（2026-09-10）

`_CG_CREATIVITY_FIXED` 新增第 (g) 條：創意階梯叫模型挑一個主視覺時，**地圖不在可選清單裡**——
禁止要求帶內部縣市／州／行政區界的國家或區域輪廓，禁止「把某地反白在另一地裡面」，
最多只能是無文字的整體剪影或明說是示意的定位圖。

這是止血，不是解法：它擋掉「創意階梯順手叫出一張錯的地圖」，但沒有讓地圖變對。

## 未做（待裁決）

1. **把守門條文改成預設就有**：把 `elif map_scope_guard:` 放寬成「明確指定非地圖類型時也注入
   `MAP_SCOPE_GUARD_RULES`」。成本是每則非地圖新聞多一小段約束（約一段，不是整塊
   `MAP_ACCURACY_RULES`），效益是這個漏洞從結構上關掉。
2. **縣市界圖層**：取臺灣縣市界圖資，比照 `map_lookup.render_basemap` 做成確定性圖層。
   這才是真正把行政區界畫對的唯一路徑。
