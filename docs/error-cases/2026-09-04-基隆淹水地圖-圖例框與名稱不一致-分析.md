# 2026-09-04 基隆淹水地圖：圖例框、指令詞入圖、同一地點兩種名稱

案例圖：[`2026-09-04-基隆淹水地圖-圖例框與名稱不一致.png`](2026-09-04-基隆淹水地圖-圖例框與名稱不一致.png)

正式站（Cloud Run，`openai/gpt-5.6-terra`）2026-09-04 19:03 的地圖類生成，
是**真實 OSM 底圖上線後的第一張成品**（`[map] 已附上真實底圖（3 個標點，681282 bytes）`）。
地理位置本身是對的——三個標點都落在正確街廓，底圖那條沒問題。錯的是文字與標記的表現。

## 現象

一張圖上同時出現四個問題：

1. **左下角多了一個藍色圖例框**，框裡兩列：「標示／基隆廟口」「標示／西定路 與 大武崙」。
2. **「標示」兩個字被畫進圖裡**——那是指令，不是內容。
3. **同一個地點兩種名字**：地圖上的 pin 標籤寫「基隆廟口夜市」，圖例框裡寫「基隆廟口」。
4. **pin 與底圖圓點分成兩個位置**：底圖的橘色圓點被模型畫成地面漣漪，pin 浮在漣漪的正上方。

## 根因（全部在消化端，與地理／geocode 無關）

從 GCS 歷史紀錄 `gs://tvbs-aicg-history/generations/20260904/110307-432301499534.json`
取出當次送進生圖的完整 prompt，比對 Cloud Run 日誌，四個現象各有明確出處：

### 一、二：圖例框與「標示」

消化端寫出來的 VARIABLE FIELDS 是：

```
[標題] 基隆市多處地區
淹水
[內文小標] 標示<基隆廟口>
[內文小標] 標示<西定路>與<大武崙>
<蓋章> 多處地區淹水
```

生圖模型逐字渲染 `variable`，兩行 `[內文小標]` 就成了畫面左下角那個框，
「標示」也就跟著被畫了出來。**模型沒有自作主張生一個圖例——它照做而已。**

真正的問題是消化端把「要標哪三個地點」當成內文小標在寫：那三個地名早就
以 pin 標籤的形式出現在地圖上了，寫第二次只是重複，還吃掉地圖的版面。
`[內文小標]` 該寫的是新聞本身（淹到哪、多深、什麼時候），不是地名清單。

### 三：基隆廟口 vs 基隆廟口夜市

日誌：`[map] 已定位 3 個地點：基隆廟口夜市、西定路、大武崙`。
消化模型為了讓 Nominatim 查得到，在 `map_places` 用了官方全名「基隆廟口夜市」——
這是對的，那個欄位就是查詢字串。錯在它把同一個字串**也**寫進了 `structure`：

> Mark 基隆廟口夜市 at 25.1284°N, 121.7419°E, 西定路 at ...

`structure` 會影響畫面上的標籤，`variable` 用的卻是新聞慣用的「基隆廟口」，
於是同一張圖上出現兩種寫法。

順帶一提，同一則的第一次嘗試（`finish=length` TRUNCATED 那次）`structure` 寫的是
乾淨的「基隆廟口」——這個病灶是隨機出現的，不是每次都會犯。

### 四：pin 浮在漣漪上方

`USER_REFERENCE_MAP_RULES` 只說「把圓點重新設計成本圖風格的 pin」，沒有說
**pin 的哪個部位要對準圓點**。模型的解法是把圓點留在原地變成漣漪、另外畫一顆
pin 浮在上面，等於一個地點給了兩個位置，而真正的座標是下面那圈。

## 修法（2026-09-04）

消化端 `MAP_ACCURACY_RULES`（`main.py`）新增三條，並在規則 11 補一句：

- **14**：地圖上的標記本身就是地名標籤，不准再做圖例／key／圖例框／地名清單小標；
  地圖能有的附件只有規則 2 的指北針與比例尺。
- **15**：標示／標出／請標／標記／位置如下 這類指令詞不准留在 `variable`，
  因為 renderer 逐字印。
- **16**：一個地點一種寫法。官方全名只准出現在 `map_places`，
  `structure` 與 `variable` 一律用新聞慣用簡稱，且兩者互相一致。
- 規則 11 補一句：`map_places` 的內容永遠不會被畫出來，畫面上的名字由規則 16 管。

生圖端 `USER_REFERENCE_MAP_RULES`（`news_prompt.py`）新增一條：pin 的**尖端**
必須壓在圓點中心，不准把 pin 的圓頭對準圓點、不准讓 pin 浮在圓點上方、
不准把圓點留成獨立的環／漣漪／光暈。

回歸測試：`tests/test_map_accuracy.py::DigestWordingTests`、
`tests/test_map_reference_wiring.py::test_the_pin_tip_must_land_on_the_dot`。
