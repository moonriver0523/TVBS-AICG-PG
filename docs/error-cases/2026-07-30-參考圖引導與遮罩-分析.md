# 第五輪：參考圖引導與遮罩硬約束實驗（2026-07-30，`feat/guide-image-safe-area`）

> 這是安全框系列的**最後一輪探索**。前四輪都在文字通道裡調措辭（像素／百分比／純文字／
> 純文字 R4 對照），本輪改試唯一還沒試過的兩條非文字通道：餵模型一張引導圖，
> 以及用 API 遮罩做硬約束。兩條都失敗，安全框自此改由後端程式化置框解決
> （見文末「處置」與 `safe_frame.py`）。

## 為什麼要做這輪

`2026-07-23-百分比安全框-分析.md` 結論 4 已經指出「空間精準問題靠 prompt 永遠不收斂」，
但當時的推論是「只能換通道（bounding box／ControlNet／底圖參考）」。
那三個替代通道從未實測過。本輪的目的就是把「換通道」這個假設驗證掉——
特別是**遮罩**，因為它理論上不需要模型聽話：API 保證遮罩保護區不動，
留白就成了介面層的硬保證而非模型的自律。

## 實驗設計

過去幾輪的最大教訓是「n=1～2 的差異會被模型隨機性淹沒」（R4 分析結論 2），
以及「邊距只有目測比例、不同輪之間不可比」。這輪針對兩點都做了處理：

- **共用同一份 digest**：`scripts/fixtures/digest-layout-test.json`，刻意採用歷史失敗率
  最高的版型（三張並排資訊卡＋底部總結橫幅）。各 arm 之間只差一個變因。
- **對照組與 production 逐字相同**：`tests/test_guide_experiment.py` 用測試釘住
  baseline arm 的 prompt 必須與 `main.generate_news_image()` 的組法一字不差，
  否則「對照組」本身就不是基準。
- **改用客觀量測取代目測**：新增 `scripts/measure_safe_area.py`（邊緣密度法）。
  以歷史案例回測驗證過可信度——烏克蘭案量到底部 10.07%（文件記錄目測 10.1%）、
  恩智浦案量到左右 26.04%／25.78%（記錄 26%），誤差在 0.1 個百分點內。
- **模型不換**：引導組與對照組都用 `gemini-3-pro-image`，與 production 的
  `google/gemini-3-pro-image` 同一個模型，只是因為 OpenRouter 撞週用量上限而改走原生 API。

三種機制、五張圖：

| arm | 機制 | 附的圖 |
|---|---|---|
| 對照組 | 現行純文字安全框規則 | 無 |
| 構圖範例引導 | 同上＋引導圖 | 黑底＋安全區內灰色版位方塊（標題條／三卡／結論條） |
| 亮暗色塊引導 | 同上＋引導圖 | 中央亮灰、四周深灰 |
| 綠邊引導 | 同上＋引導圖 | 中央亮灰、四周純綠（專測滲色） |
| GPT 遮罩 | `images.edit`＋遮罩硬約束 | 純色底圖＋安全區透明的遮罩 |

引導圖一律**不含任何文字或數字**（前四輪教訓：圖上有字會被照抄），
產生器見 `scripts/make_safe_frame_guide.py`，並有測試驗引導圖自身不違規、顏色數 ≤3。

遮罩組另外做了一項調整：把文字版留白規則與消化的「縮小置中留厚邊」強制開頭句都移除，
改成「畫滿可編輯區」。因為留白已由遮罩保證，若再要求模型自己留邊會二次縮小成過縮浪費。

## 量測結果

官方需求：上 10.09%／左 7.29%／右 7.60%／下 20.37%，四邊獨立判定。

| arm | 上 | 左 | 右 | 下 | 合格邊 |
|---|---|---|---|---|---|
| 對照組 | 7.81 ❌ | 12.86 ✓ | 12.86 ✓ | 11.20 ❌ | 2/4 |
| 構圖範例引導 | 11.98 ✓ | 6.47 ❌ | 6.47 ❌ | 8.46 ❌ | 1/4 |
| 亮暗色塊引導 | 7.29 ❌ | 10.76 ✓ | 10.76 ✓ | 9.24 ❌ | 2/4 |
| 綠邊引導 | 8.20 ❌ | 10.97 ✓ | 10.76 ✓ | 13.67 ❌ | 2/4 |
| GPT 遮罩 | 5.97 ❌ | 0.08 ❌ | 0.08 ❌ | 2.50 ❌ | 0/4 |

**五張全不合格。底部安全區 0/5，一次都沒有。**

## 四個結論

### 1. 引導圖影響「排列」，不影響「比例」

構圖範例那張的骨架明顯照抄了引導圖（標題橫條在上、三張並排卡在中、結論條在下），
但尺寸完全自己來——左右反而比對照組更薄（6.47% vs 12.86%）。
**模型把引導圖當構圖靈感，不當座標系。** 這與前四輪的病灶其實是同一個：
模型有版面的「語意概念」，沒有版面的「度量能力」。換成圖片通道也沒有給它度量能力。

### 2. 遮罩不是硬約束——`gpt-image-2` 整張重繪

這是本輪最重要的一項，也是實驗前預期最可能成功、結果卻最徹底失敗的一項。
遮罩被完全無視：我給的純色底圖在留白區被換成世界地圖與 K 線背景，左右留白 0.08%。

查證確認這是 OpenAI 已承認的已知限制——gpt-image 系列的遮罩是「軟遮罩＋整張重繪」，
不做 DALL·E 2 那種像素級替換。唯一可能提升保留度的參數 `input_fidelity` 直接回
400 `invalid_input_fidelity_model`，`gpt-image-2` 不支援。

**所以「靠 API 層硬性保證留白」這條路在 OpenAI 這邊是關死的**，
不是措辭問題、不是參數沒調對，是模型能力邊界。

### 3. 「引導圖不是配色參考」這句防護有效

連四周純綠那張都沒把綠色帶進輸出。對照前四輪「防護句往往反效果」的經驗
（如 `NEVER draw rulers` 反而誘發工程圖標註），這次的防護句是有效的。
兩者的差別值得記住：**否定某個具體繪圖動作容易反效果，聲明某個輸入的用途則有效。**
（綠邊那張配色偏青，但基準風格本來就寫了 cyan accent，不足以認定是引導圖影響。）

### 4. 反過來得到最有用的一項：模型「畫滿」做得非常好

遮罩組雖然機制失敗，但它證明了另一件事：當我把留白規則全部拿掉、改叫它畫滿可編輯區，
它就真的畫得滿滿當當、四邊貼齊，而且繁中零亂碼、`3.8`／`12%`／`2個月` 全部正確、
括號沒有入圖。

**「要它畫滿」很容易，「要它留邊」做不到。** 這一句是本輪對後續工程最有價值的產出，
直接決定了處置方向：順著模型天性讓它畫滿，留白交給程式。

## 處置

**安全框改為後端程式化置框，同日落地**（見 `safe_frame.py`）：
滿版生成後由程式把整張圖等比縮放置入 TVBS 安全框並置中，四周補 blur-fill 背景，
輸出官方 1920×1080。安全框合格與否從此不取決於模型，改由數學保證。

端到端實測（原生 Gemini，同一份新聞原文，含消化）：

| 送出比例 | 上 | 左 | 右 | 下 | 判定 |
|---|---|---|---|---|---|
| 16:9（預設） | 10.00 ✓ | 14.74 | 15.05 | **20.28 ✓** | 四邊合格，左右偏寬 |
| 21:9 | 12.69 ✓ | 7.24 ✓ | 7.55 ✓ | **22.96 ✓** | 四邊合格且零浪費 |

底部安全區在本專案歷史上累計 0 次合格，置框後 100% 合格且可重現。
對照圖：`2026-07-30-程式化置框-四邊合格對照.png`。

21:9 因安全框本身是 2.175:1 而幾何貼合、左右零浪費，但唯一那張樣本出現括號入圖
（`[供給減少]`／`<主要產區減產約12%>`），同一份規則的 16:9 樣本則乾淨。
依 R4 分析結論 2，括號入圖是 Gemini 隨機行為，n=1 無法歸因，**故預設仍為 16:9**，
待各跑 4 張以上再定（記於 TODO）。

**未完成**：GPT 側（`openai/gpt-5.4-image-2`）的引導圖與置框實測都還沒做——
OpenRouter API key 撞週用量上限（403 Key limit exceeded），本輪只能改走原生 Gemini。
GPT 是 LINE Bot 的預設引擎，配額恢復後應補測。置框邏輯與模型無關，
理論上一體適用，但未實測不宜掛保證。

## 這輪不要再重複的事

- 安全框寫進 prompt 的路線**五輪蓋棺**：像素、百分比、純文字、純文字 R4 對照、
  參考圖引導。底部安全區累計 0 次合格。
- **遮罩不能當硬約束**（`gpt-image-2` 軟遮罩整張重繪，且不支援 `input_fidelity`）。
  若日後有人提議「用 API 遮罩鎖死留白」，先讀本節第 2 條結論。
- 引導圖可以拿來影響**排列**（若某天需要指定版型骨架，這條或許有用），
  但不要期待它能控制**比例**。
