修一項冒一項：過縮 → 貼邊 → 底部壓帶 → 括號入圖。

為什麼這一步重要
記者不必開電腦、不必進工具、不必學介面 ── 聊天室就是介面。 這也先驗證了 WORKCORD 助理的產品形態。
跑的是現行折衷版（AI 連文字一起畫），不是後面要談的混合版型 ── 所以後面那些文字風險，這裡一樣存在。現況為原型：生成需 30–120 秒，尚未接佇列與重試，仍待雲端部署。
而且這個版本仍然會錯
版面過關了，事實還是會歪
版面乾淨，乍看幾乎可以上鏡
標題整排亂碼
邊距、資料卡、來源都到位，偏偏最顯眼的主標題 是一排亂碼假字「会絥刷侢齎発…」，根本不是「美國臨時關稅」。標題垮了，整張圖就報廢。
日期、英文一起垮
日期「2024年3 19目」把「日」寫成「目」， 英文也拼錯（INVALIDVATES、EXECTED、來源 AP 變 APP）。繁中錯字與亂碼是生圖模型的老問題。
版面能過關、字卻寫不對 ──
看似各自的毛病，其實同一個根因。
學到的東西
不是提示詞不夠好，是模型量不出來
1
數字在 prompt 裡只是「一串可能被畫出來的文字」
對模型來說 288px 和 15% 沒有差別，都不是可以量測的指令。
2
提示詞工程有天花板
要做到像素級精準，通用作法都是換一條通道去下指令，而不是把話講得更清楚。
3
公司既有工具早就這樣做了
Studio Locked-Frame 的安全框，是網頁自己用畫布疊一層半透明黑、再把安全區挖空畫出來的 ── 完全沒有交給生成模型。

備用 ・ Q&A 用
開發過程的其他坑
結構化輸出的隱藏限制
要 AI 回傳固定格式的三欄資料，schema 不支援 minItems／maxItems， 欄位數量只能靠後端自己補齊與截斷。
上游偶發失敗是常態
外部模型服務會間歇性回傳錯誤或不合格式的內容， 重試機制必須涵蓋「呼叫＋解析」全程，只重試呼叫沒有用。
兩支程式合流的撞名
混合版型併進主工具時，兩邊各有同名的全域變數， 同頁載入直接整頁停擺 ── 用模組化隔離解決。
