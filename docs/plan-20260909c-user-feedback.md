## 逐項

### 1. 提示文字斜體

`index.html` 的 `<style>` 加一條全站規則（`input::placeholder, textarea::placeholder`），
不是逐個欄位加 Tailwind class——逐個加的話，之後新增欄位一定有人忘了帶。
守門：`tests/test_followups_20260909c.py::PlaceholderItalicTests`。

### 2. 整點直播的 LIVE 章與時間白框

`YT_HOURLY_BADGE_WIDTH_RATIO` 0.25 → 0.225。時間帶的**寬度**本來就是從 `badge_w` 推的、
會自己跟著縮，但**高度**是獨立常數，不一起收就會變成一塊過胖的白框，所以
`YT_HOURLY_TIME_BAND_HEIGHT_RATIO` 0.095 → 0.086（同比例）。
測試除了擋「有縮小」，也擋「只縮了一點點」（>85%）與兩者的比例不變。

### 3. 直標改名與換位

`app.js` 與 `editor_formats.py` 兩張表都要動（下拉是照物件插入順序建的），
標籤 `－YT直播直標`（全形減號 U+FF0D，照使用者寫的），位置移到 `yt_live_cover` 之後。
原本的測試釘的是「排在整點直播下面」（0908 的裁決），這次照新裁決改寫，不是刪掉。

### 4. 行距與羽化——這兩件事互相擠

行距：`YT_LINE1_BASELINE_RATIO` 0.778 → 0.790（第二行貼底不動，第一行往下靠），
行距 0.180 → 0.168。**只動國內外新聞直播與今日熱搜**：

| 版面 | 兩行行距 | 這次動了嗎 |
|---|---|---|
| 國內外新聞直播／今日熱搜 | 0.180 → **0.168** | 是 |
| YT 整點直播（雙則） | 0.150 | 否，本來就比新值還緊 |
| 十點不一樣（合成版） | 三行、`COVER_TITLE_LINE_GAP=1.06` | 否，使用者講的是兩行標 |

羽化：使用者要「邊緣再多一點漸層」，但**行距一縮，羽化就更沒地方長**——
斜坡本來就住在兩行字中間那道空隙裡。往下延會切到黃字（0908 的裁決：不超過第二行標題），
所以改成**往上多起跑一段**：

```
YT_BAND_LEAD_RATIO = 0.020
YT_BAND_TOP_RATIO  = YT_LINE1_BASELINE_RATIO - YT_BAND_LEAD_RATIO   # 0.770
YT_BAND_FADE_RATIO = 0.052    # 原 0.0365，+42%；0.770 + 0.052 = 0.822 到全濃度
```

smoothstep 在 t 很小的時候幾乎是 0（白字墨水上緣處算出來 < 8% 濃度），
那一段藏在白字腳下看不出來，卻讓整條斜坡從 26px 拉長到 37px。
全濃度處 0.822 仍壓在黃字墨水上緣 0.8231 之上——0908 那條裁決沒有被這批取消。

原本的測試 `test_the_band_starts_at_the_first_line_baseline_not_above_it` 釘的是
「帶頂不得高於第一行基線」，跟這次的做法直接衝突。改寫成量真正在意的事：
起跑點最多高 0.025，且白字墨水上緣的濃度要低到幾乎為零。**「看不出來」不能用講的。**

連帶：AI 版 prompt 裡的 78%／22% 改成從 `compose.YT_BAND_TOP_RATIO` 算
（`editor_formats` 因此 `import compose`；compose 只在函式內部反向 import，不成環）。
第三批的教訓是「模型手上有什麼數字就抄什麼」，所以那個數字絕不能是手抄的。

### 5. 十點 AI 設計標題完全解放

對應既有的「設計標題」開關（`title_style: plain | designed`）。
**plain 完全不動**（白／黃／紅逐行配色、版位固定），出事把開關關掉就回得去；
`designed` 從「只改大小與位置」升級成整段 OVERRIDE。

解放：字體、顏色、描邊與陰影、裝飾邊框、強調手法、版位、行的擺法。
明文點名取消前面三條（逐行配色、鎖在左下、一行一列）——含糊帶過模型會照舊保守辦。

**要按亮「設計標題」鈕才生效，預設仍是 plain（白／黃／紅）。** 這是把使用者原話
對應到既有開關的判讀——「AI 設計標題」有兩種讀法（標題由 AI 生成 vs 設計標題 ON），
選了可逆的那一種。要預設就解放的話，`app.js` 的 `coverTitleStyle: 'plain'` 改成
`'designed'` 一行的事。

**不解放**（寫在同一段的第二個 bullet 裡）：
一個字都不能加減改；**一行的中間不准斷**（`9/12` 被拆成兩行就是最典型的一種）；
正體中文臺灣字形；上下兩條深藍帶不得被字蓋掉；標頭帶左半與 AI示意圖 那個角落要留空
（那兩處是 `compose.paste_cover_logo` / `paste_cover_ai_note` 後貼的）；不得有其他文字；不得出血；**雙切版每個標題留在自己那格、不得跨過斜切線**
（解放的是「在自己那格裡的哪個位置」，不是「哪一格」）。

### 6. Logo 掉出標頭帶

**根因不是 Logo 太大。** 實測模型畫的帶只有 62/720 = 8.6%（另一張 58/720 = 8.1%），
prompt 寫的是「about one tenth」，而 `paste_cover_logo` 按寫死的 10% 算位置與大小，
Logo 底就剛好戳到藍線外面。

修法照本 repo 對挖空框的同一個原則——**不靠模型自律**：新增
`compose.measure_ai_header_band()`，在畫面中段（左邊是 Logo／節目標籤、右邊是日期／ON AIR，
中間一定是空的）取數條直線，各自往下找第一列顏色明顯不同於第 0 列的位置，取中位數。
量到的值超出 5.5%–14.5% 就是量錯（模型多畫了裝飾，或帶跟照片同色），退回寫死的一成。
再從量到的帶高扣 12% 當空隙，Logo 與節目標籤都據此縮放置中。`paste_cover_ai_note`
也改用同一個量出來的高度，不然帶薄的時候小標會浮在帶子裡面。

只把 prompt 改嚴（「exactly one tenth」）不算修好——這個專案已經證明過那不管用。

**同根因的第二處**：`_draw_cover_highlight_stamp`（精華標籤）用的是更大的
`COVER_HEADER_RATIO`（10.5%），AI 版一樣會戳出帶外。使用者沒回報是因為平常不開精華，
不是因為它沒事。改成收一個 `band_h` 參數：AI 那條線傳量到的值，合成版傳 None
（它的帶是程式自己畫的，高度一清二楚，不必也不該去量）。
