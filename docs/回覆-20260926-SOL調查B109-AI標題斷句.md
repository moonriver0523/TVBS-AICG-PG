結論：主因不在生圖 prompt 要求「每行 N 字」，而是送進生圖模型前就已經切錯。十點不一樣的 AI 標題模式被 B75 刻意跳過 B108 詞組斷句，隨後又由本地 7 字寬度邏輯硬切；YT 則另有 AI 消化 prompt 的「每段 5–12 字」可能先產生不自然分段，且 news／hourly／hot 的最終 prompt 對「不得重新換行」約束不如 live24 明確。

全程只讀，未改檔、未呼叫付費 API；相關 37 項測試均通過，但現有測試剛好沒有覆蓋「B75 跳過 B108 → 最終 prompt 已切壞」這個交叉情境。

## 關鍵證據與真因

### 1. 十點不一樣：B75 的前提已不成立

`apply_title_break_hints(..., composite=False)` 會清空 hints 並直接返回；註解認為 AI 生圖「不會讀 hints」：

- [main.py:6626](E:/GitHub/TVBS-AICG-PG/main.py:6626)
- [main.py:6642](E:/GitHub/TVBS-AICG-PG/main.py:6642)
- 滿版／雙切入口確實只在 composite 模式呼叫斷句模型：[main.py:7802](E:/GitHub/TVBS-AICG-PG/main.py:7802)

但 AI 生圖路徑其實會呼叫 `compose.cover_title_lines()`，它會讀取相同的 `_BREAK_HINTS`，再把結果逐行寫進 prompt：

- `_lines_block()` 呼叫排字邏輯：[main.py:6893](E:/GitHub/TVBS-AICG-PG/main.py:6893)
- 寫入 `exactly N lines`、`Line 1/2/3`：[main.py:6907](E:/GitHub/TVBS-AICG-PG/main.py:6907)
- 滿版／雙切皆使用該行清單：[main.py:6958](E:/GitHub/TVBS-AICG-PG/main.py:6958)

因此 B75 不是只省掉無效呼叫，而是讓 AI prompt 失去 B108 詞組邊界。

無付費 API 的純函式重現：

```text
原標題：王鴻薇揭露歐洲中央銀行政策

AI 模式／B75 跳過 hints：
王鴻薇揭
露歐洲中
央銀行政策

套用 B108 詞組：
王鴻薇揭露
歐洲中央銀行
政策
```

本地排字在沒有 hints 時，最後會採接近中點／寬度的 fallback；程式註解也承認此時「實詞沒有規則擋得住」：

- hints 優先與 fallback：[compose.py:1273](E:/GitHub/TVBS-AICG-PG/compose.py:1273)
- 7 字填行目標：[compose.py:1327](E:/GitHub/TVBS-AICG-PG/compose.py:1327)
- 滿版、雙切最多 3 行：[compose.py:585](E:/GitHub/TVBS-AICG-PG/compose.py:585)
- B108 長詞組寧可縮字、不拆詞：[compose.py:1260](E:/GitHub/TVBS-AICG-PG/compose.py:1260)

B108 的文字模型指示本身已正確規定「詞語完整優先於均衡／字數」並附例：

- [editor_formats.py:1060](E:/GitHub/TVBS-AICG-PG/editor_formats.py:1060)

### 2. YT：有兩條不同的分行來源

YT news／hourly 單題／hot：

1. 若標題恰有一個半形空白，直接視為人工指定的兩行。
2. 否則由 `derive_yt_cover_plan()` 要 AI 消化模型產出 `line1`、`line2`。
3. 最後再把兩行送給生圖模型。

證據：

- 一個空白即鎖定兩行：[editor_formats.py:1158](E:/GitHub/TVBS-AICG-PG/editor_formats.py:1158)
- derive 要求產生或照抄兩行：[main.py:8091](E:/GitHub/TVBS-AICG-PG/main.py:8091)
- B108 已加入 derive system prompt：[editor_formats.py:2338](E:/GitHub/TVBS-AICG-PG/editor_formats.py:2338)
- hints 驗證與 fallback：[main.py:8197](E:/GitHub/TVBS-AICG-PG/main.py:8197)

問題是 YT AI 標題消化 prompt 仍要求「正好兩段、每段 5–12 字」，卻沒有 B108 的詞語完整優先規則：

- 一般 YT：[editor_formats.py:1307](E:/GitHub/TVBS-AICG-PG/editor_formats.py:1307)
- hourly 單題：[editor_formats.py:1468](E:/GitHub/TVBS-AICG-PG/editor_formats.py:1468)

這個輸出被前端填回單一標題欄位：

- 消化結果回填：[app.js:2690](E:/GitHub/TVBS-AICG-PG/static/app.js:2690)
- 呼叫生圖時仍只送一個 `title` 字串，沒有 `title_line1/2` 請求欄位：[app.js:2782](E:/GitHub/TVBS-AICG-PG/static/app.js:2782)

只要消化結果帶一個空白，後端就把該空白視為已裁定分行，不再重新評估詞組完整性。這是 YT 最明確的前段風險。

## 修法比較與建議

| 方案 | 預期效果 | 延遲／成本 | 主要修改處 | 判斷 |
