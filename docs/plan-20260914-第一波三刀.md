## 動工前查證到的三件事（改變了計畫形狀）

### 1. 凍結測試只釘兩檔，不是五檔

`tests/test_reporter_prompt_frozen.py` 的迴圈是 `for density in ("standard", "simplified")`，
四份 fixture ＝**這兩檔 × 安全框開關**。`maximum`／`minimal`／`verbatim` 是**疊加**在
這兩檔之上的獨立區塊，改它們**不破 fixture**。

**這給了第二刀一條省事的路（見下方「往外撐」原則）。**

同時要記得那份 docstring 的鐵律：**「記者的 prompt 一個字都不准變」**（2026-08-17 使用者要求）。
真的要動時才連同快照一起更新，並在 docstring 補一條說明——
已有兩次前例（2026-09-09 字多放寬、2026-09-10 地圖守門），照同樣格式寫。

### 2. 附圖順序本來就送得出去——D9 是措辭改動，不是新增欄位

原本以為 CG 線 `shared_refs=True` 會把上傳順序攤平。**查證後不成立**：

- `_native_reference_files`（main.py:2983）：`sources.extend(ref.data_url for ref in req.reference_images)`——list 順序原樣
- OpenRouter 路徑（main.py:2895）：同樣是 list 推導，順序原樣
- `asis_left`／`asis_right` 的註解（main.py:3997）已明寫「兩欄都空時才退回上面
  `reference_images` 的 **asis 順序規則**」——順序概念早就存在，只是 CG 線沒用上

被攤平的是 `dict.fromkeys(ref.purpose ...)`（main.py:3583）——那攤平的是**用途**，不是圖。

⚠ **編號陷阱**：兩條路都把 `reference_image_data_url` 與 `portrait_reference_data_urls`
**排在使用者上傳之前**。所以 prompt 講「attached image 1」時，那不一定是使用者心裡的第 1 張。
措辭必須綁**使用者上傳的那一組**，不能直接用全域序號。

### 3. A1 的前置是一次真的重構

池子本身在 `creativity.py`，但件數表 `COVER_ACCESSORY_COUNTS`（`editor_formats.py:574`）
與抽法 `cover_accessories()`（`editor_formats.py:649`）留在 editor_formats，
註解明寫「**十點專屬，跟 titles／full_width 耦合，不是跨拉桿共用的機制**」。
CG 線要共用就得先拆這個耦合——**這不是接線，是搬家＋去耦合。**
