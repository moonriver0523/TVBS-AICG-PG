# 範例：TVBS 官方安全框工具（Studio Locked-Frame）

> 建立日期：2026-07-24
> 來源：https://tools.tvbs.ai/tools/locked-frame/ （TVBS AI Tools 內建工具，暱稱 "Gemini Safe-Zone Image Extender"）
> 用途：這是公司既有的、非本專案的官方安全框標準與實作參考，記錄下來供本專案的混合版型（[hybrid-rendering-proposal.md](../hybrid-rendering-proposal.md)）核對安全區數值與畫框做法，並作為未來生圖自動驗收的基準。

## 一、安全框標準數值（實測，2026-07-24）

- 基準畫布：**1920 × 1080**（16:9，1080P）
- 安全框座標：**X=140, Y=109, W=1634, H=751**
- 四邊留白換算：
  - 上：109px（10.09%）
  - 左：140px（7.29%）
  - 右：146px = 1920-140-1634（7.60%）
  - 下：220px = 1080-109-751（20.37%）
- 上下左右**不對稱**，下方留白明顯較大（推測預留跑馬燈／下方字卡空間）
- 面板上有「🔒 MASK DIMENSIONS LOCKED」標示，代表這組座標是固定標準，不隨素材拖曳而改變——只有素材本身可以移動、安全框永遠固定在原位

## 二、與本專案 safeArea 的對照

`docs/hybrid-rendering-proposal.md` §三版型範例目前是（1280×720 基準）：

```json
"safeArea": { "top": 72, "left": 80, "right": 80, "bottom": 144 }
```

換算成百分比：上10%／左6.25%／右6.25%／下20%。

對照 TVBS 官方數值（上10.09%／左7.29%／右7.60%／下20.37%），**兩者非常接近**，上下比例幾乎一致，只有左右留白 TVBS 版略寬且不對稱。這算是對現有 `safeArea` 草案的一次獨立交叉驗證——比例抓得沒錯，但左右可以再放寬一點、且不必強制對稱。

**待辦**：正式製作版型時，把 `safeArea` 改成跟 TVBS 官方一致的非對稱數值（1280×720 換算：**上 73px／左 93px／右 97px／下 147px**），而不是目前對稱的 80/80。

> 算術修正（2026-07-30）：本行原寫「上≈129px／下≈261px」是把上下比例乘到**寬度**（1280）上的結果，正確應乘**高度**（720）：上 0.1009×720≈73、下 0.2037×720≈147。左右兩個數字原本就是對的。照舊值實作會把上留白做成 17.9%、下留白做成 36%。正確換算已由 `safe_area_spec.required_margins_px()` 提供，並有 `tests/test_safe_area_spec.py` 釘住，不要再手算。

## 三、畫框的實作方法（用瀏覽器 DevTools 讀取頁面 DOM／JS bundle 驗證，非猜測）

檢查 https://tools.tvbs.ai/tools/locked-frame/ 的「工作區預覽」DOM 結構，發現**整個預覽只有一個 `<canvas>` 元素**，沒有任何用來畫暗色遮罩的 `<div>` 覆蓋層、CSS `box-shadow`（spotlight 技巧）或 `clip-path`。也就是說暗色安全框**不是疊 CSS 圖層做出來的**，而是畫布本身直接畫出的像素。

進一步抓取它載入的 JS bundle（`index-BkokAr6p.js`），在同一段程式碼附近找到以下關鍵字排列在一起：

- `getContext`
- `drawImage`
- `clearRect`
- `rgba(0,0,0…)`（半透明黑色）
- 變數名 `safeZone`

對應的標準畫法：

1. 先把上傳的素材整張用 `drawImage` 畫到 canvas 上
2. 再用半透明黑色 `rgba(0,0,0,alpha)` 蓋滿整個畫布（fillRect 全畫布）
3. 最後把安全框矩形（X/Y/W/H）範圍「挖空」還原成原圖像素（用 `clearRect` 配合重畫該區域，或分別處理上下左右四條色帶），只留安全框內部維持清晰、四周維持變暗

`canvas.width / canvas.height` 讀出來正是 `1920 / 1080`，與面板顯示的基準畫布一致。

整個過程是前端即時 render，**沒有呼叫後端 API 做圖片處理**，也沒有依賴生成模型把安全框「畫」進圖裡——這正好呼應 `docs/hybrid-rendering-proposal.md` 與 TODO 裡「安全區像素/%論戰」的結論：生圖模型量不出像素，安全框只能靠 APP／畫布自己疊加，不能交給生成模型的 prompt 去猜。

## 四、生圖自動驗收基準（2026-07-24 起生效）

**未來凡是自行測試／驗收生圖結果是否符合安全框，一律以本文件第一節的官方數值為基準**，不要另外發明比例或沿用舊的對稱 80/80 草案。

換算成任意輸出解析度都能用的百分比公式（W=畫布寬，H=畫布高）：

| 邊 | 留白比例 | 安全區起訖（相對座標） |
|---|---|---|
| 上 | 10.09% | 安全區從 `0.1009×H` 開始 |
| 左 | 7.29% | 安全區從 `0.0729×W` 開始 |
| 右 | 7.60% | 安全區到 `0.9240×W` 為止（= 1 − 0.0760） |
| 下 | 20.37% | 安全區到 `0.7963×H` 為止（= 1 − 0.2037） |

也就是安全區實際可用範圍約為畫布中央 **85.11% 寬 × 69.54% 高** 的矩形（且不是置中，偏上偏左）。

**合格判定**：標題、文字、關鍵資訊、跑馬燈遮擋區等重要視覺元素，不得出現在上述安全區矩形之外。四邊各自獨立判定（例如即使左右合格，只要底部有元素超出 79.63% 高度線，仍視為不合格）。

驗收時建議做法：用生圖實際輸出解析度換算出四條邊界線的像素座標，再檢查關鍵元素（文字框、logo、圖表、下方跑馬燈遮擋區等）的 bounding box 是否完全落在邊界線內側。

## 五、對混合版型工程的參考價值

若混合版型的編輯器（`hybrid.html`/`hybrid.js`）未來要加「即時安全框預覽」功能，可以直接沿用這個工具驗證過的做法：

- 用同一張 `<canvas>` 疊加半透明黑遮罩＋挖空安全區，不需要額外 DOM 圖層
- 安全框座標比照本文件的官方比例（見上方換算），而不是自訂一組新數字
- 「MASK DIMENSIONS LOCKED」的 UX 概念也值得借鏡：安全框本身鎖定不能拖動，只有內容/素材可以在框內移動，避免使用者不小心把安全框拉歪
