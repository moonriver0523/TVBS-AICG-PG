# 交辦：B39 — `/api/generate` 改串流＋心跳，讓 Cloudflare 不再 524

**執行**：實作 session ／ **驗收**：AICG 監督 session
**分支**：`exp/redesign-20260903`
**裁決狀態**：使用者 2026-09-15 已裁 ✅ **改串流＋心跳**，公司 Cloudflare 的 proxy timeout **不能調**。
**排程**：**必須等 B38 收工後才動工**。兩件事都在改錯誤的表示法，同時動會打架。

---

## 一、要解的問題

2026-09-15 正式站實拍：2,930 字稿 ×「字超多」× 資料圖表，**約 122 秒收到 HTTP 524**
（Cloudflare "A timeout occurred"），死在消化那發 `/api/generate`。

程式裡三道預算全部比 CF 的切線大——前端 `DIGEST_FETCH_TIMEOUT_MS=290`、
後端 `DIGEST_DEADLINE_SECONDS=230`、單次 `DIGEST_TIMEOUT_SECONDS=90`，
註解還明寫「時間設在 Cloud Run 的 300 秒之內，讓後端的訊息永遠有機會先回來」。
**那個前提是錯的**：真天花板是 CF 約 100–120 秒，後端根本來不及回它那個 503。
連帶 `DIGEST_ATTEMPTS=5 × 90 秒` 的重試設計在 CF 底下連兩輪都跑不完，形同虛設。

**524 的定義是「源站在時限內一個字都沒回」。** 只要連線上持續有位元組流動就不會觸發。
所以不必讓工作變快，只要**別讓連線靜默**。

---

## 二、做法

### 後端：`/api/generate` 改成串流

`main.py:2238` 那條端點目前回 pydantic response model。改成 `StreamingResponse`，
格式用 **NDJSON**（`application/x-ndjson`，一行一個 JSON 物件）：

```
{"type":"ping"}                        ← 處理期間每 5~10 秒送一行
{"type":"ping"}
{"type":"result", ...原本的回應內容... }   ← 成功，最後一行
```
失敗時最後一行改成：
```
{"type":"error","status":503,"detail":"…後端原本要回的那句話…"}
```

實作要點：
- 消化本體丟到背景執行緒跑，主生成器一邊等結果一邊定時 yield 心跳。
- **心跳間隔要明顯小於 CF 的切線**，取 5～10 秒；不要壓到 1 秒，那只是白費頻寬。
- `DIGEST_DEADLINE_SECONDS=230` **維持不動**——Cloud Run 的 300 秒硬上限還在，230 仍是對的。
- `X-API-Key` / Clerk 那道 `Depends(verify_internal_api_key)` **原樣保留**。

### ⚠ 最大的坑：狀態碼在第一個位元組送出後就定死了

一旦開始串流，HTTP status 就固定是 200，**不能再改成 503**。所以：
- **所有錯誤都必須編在串流內容裡**（上面的 `{"type":"error"}`），不能靠 status code。
- 前端必須改成**看內容判斷成敗**，不是看 `response.ok`。
- 這正是要排在 B38 之後的原因：B38 剛改完 `_apiError()`，這裡要讓兩邊對齊，
  **B38 產出的那套人話訊息要繼續沿用**，不要另外造一套。

### 前端：`_digestFetch` 改讀串流（`app.js:2199`）

- 用 `response.body.getReader()` 逐行讀，遇到 `{"type":"ping"}` 就忽略（可順便推進度條，讓使用者看到它還活著）。
- 讀到 `{"type":"result"}` 當成功；讀到 `{"type":"error"}` 走 B38 那條錯誤橫幅。
- `DIGEST_FETCH_TIMEOUT_MS=290` 的 `AbortController` **保留**，但語意變成
  「整趟串流的上限」，註解要跟著改寫，不要留著已經不成立的舊理由。
- 串流中途斷線（reader 拋錯）也要走錯誤橫幅，訊息要跟逾時區分開。

## 三、邊界

1. **不要改任何 prompt 文字**（凍結快照，本波無重凍預算）。
2. **不要調 `DIGEST_DEADLINE_SECONDS`／`DIGEST_TIMEOUT_SECONDS`／`DIGEST_ATTEMPTS`
   任何一個數字。** 這輪只換傳輸方式，不動預算——動了就沒辦法判斷是哪一邊起的作用。
3. **不要動 `digest_reasoning_body()`**（B41，未裁）。
4. **只動 `/api/generate` 這一條**。`/api/images/generate`、`/api/hybrid/digest`、
   `/api/news-image/generate` 都不在本單範圍（`/api/news-image/generate` 另有把消化與生圖
   包在同一發請求的問題，尚未開單，本波不碰）。
5. 只動 `exp/redesign-20260903`。
