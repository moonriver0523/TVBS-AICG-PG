# 上傳圖片統一模組化＋新用途「AI改圖」（2026-09-13）

使用者原話：

> 十點不一樣／YT整點直播 上傳圖片 現在只有放置，要跟其他地方的上傳圖片功能對齊。
> 可以上傳多張。可以選擇原圖放置(預設) 或新增的選項 "AI改圖"。
> 全站所有上傳圖片功能都要統一 (模組化?)。
> 上傳後的選單列表 順序: 原圖放置(預設) / AI改圖 / 實景參考 / 肖像照片 / 地圖底稿

## 動工前的三處分歧

| | 共用附圖區 `refUploadBox` | 十點 `coverAsis` | 整點 `ytAsis` |
|---|---|---|---|
| 張數 | 最多 3 張 | 每格 1 張 | 每格 1 張 |
| 用途下拉 | 有（4 種） | 無（固定原圖放置） | 無（固定原圖放置） |
| 預設用途 | `scene` | — | — |
| 讀檔／壓縮 | 自己一份 | 自己一份（複製） | 自己一份（複製） |
| render | `renderRefUploads` | `renderCoverAsis` | `renderYtAsis` |

三份讀檔邏輯逐字相同，三份 render 各寫一次。模組化就是把這三份收成一份。

## 裁決（2026-09-13 使用者）

1. **AI改圖 ＝ 以這張圖為底重繪**：上傳圖當底圖送給生圖模型重畫成版型風格，
   主體與構圖保留但整張是 AI 畫的。與「原圖放置」差在會被重畫，與「實景參考」
   差在成品直接源自這張圖、不是只拿來參考。
2. **AI改圖的成品要標「AI示意圖」**：畫面是 AI 重繪出來的，不是真實新聞照。
   ＝把 aiedit 排除在 `USER_REFERENCE_NO_DISCLAIMER_RULES` 那條豁免外。
3. **AI改圖不強制程式壓字**：現行強制的理由是「真實新聞照交給模型重畫會走樣」，
   AI改圖 本來就是要重畫，那個理由不成立；標題交回創意階梯決定。

## 不動的既有裁決

* **一標一附圖不推翻**（2026-09-10）：十點／整點的左右格＝左右附圖位。
  「可以上傳多張」是**每一格可以放多張**，不是回去用共用清單。
  `hides.refUpload` 維持開著——模組現在住在格子裡，共用區仍是重複入口。
* 一格只放得下一張圖：每格**第一張 `asis`** 才是那格的版位圖，同格其他張
  （aiedit／scene／portrait／map）是那格生圖時的參考。同格放第二張 asis 會
  被忽略並 toast，不靜靜吞掉（照 repo「只取前 N 張＋print」慣例）。

## 預設改成「原圖放置」的連帶影響（刻意）

共用附圖區的預設用途原本是 `scene`，改成 `asis` 之後：

* 主流程 CG：附一張照片預設就是「原封不動放進成圖」，且 `uploadedAsisCount`
  會讓消化端保留版位、封面端強制 composite。
* YT 國內外新聞直播／今日熱搜：asis 張數決定版面（1 整版／2 雙切／3 三切），
  所以多附一張的預設行為從「多一張參考」變成「改版面」。

使用者要的就是全站統一，照做；這段寫下來是為了日後查為什麼行為變了。

## 落地

### 共用詞彙（唯一真相源）

`editor_formats.REF_PURPOSE_ORDER`：`[(key, label)]` 依使用者指定順序，
`REF_PURPOSE_DEFAULT = "asis"`。app.js 照抄一份，由 parity 測試釘住
（比照既有的 `test_prompt_parity`）。**刻意用有序陣列而不是 dict**：
使用者明確指定了下拉順序，靠 JS 物件鍵序來保證順序太脆。

### 後端

* `UserReferenceImage.purpose` Literal 加 `"aiedit"`。
* `news_prompt.USER_REFERENCE_AIEDIT_RULES` ＋ 註冊進 `USER_REFERENCE_MODES`。
* `apply_user_references_to_image_request`：有 aiedit 就不注入
  `USER_REFERENCE_NO_DISCLAIMER_RULES`（裁決 2）。
* 附圖位欄位由單一 data URL 字串升成清單：
  `slot_left: list[UserReferenceImage]` / `slot_right`（十點與整點兩個請求模型各一份）。
  舊的 `asis_left` / `asis_right` 字串**保留**並在讀取時正規化成單張 asis 清單——
  既有測試與舊呼叫端（LINE）一字不用改。

### 前端

* `readImageFile(file)` 一份取代三份 FileReader／壓縮區塊。
* `renderRefList(listEl, items, onRemove)` 一份取代三個 render。
* `state.coverAsis` / `state.ytAsis` 由 `{left: obj, right: obj}` 變成
  `{left: [], right: []}`；送出時組 `slot_left` / `slot_right`。
