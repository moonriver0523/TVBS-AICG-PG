## 一、為什麼要修

2026-09-15 在正式站重現曹雪卿說的「生圖很容易失敗」：
2,930 字稿 ×「字超多」× 資料圖表，約 122 秒後收到 **HTTP 524**（Cloudflare 逾時）。

現場長這樣：進度條卡在「消化新聞 35%」約一分鐘後**靜默歸位**成初始紅色按鈕，
「生成結果」欄**還留著上一次的舊圖**，使用者看起來像什麼都沒發生。

`handleOneClickGenerate` 的 catch 裡**有** `showToast(err.message)`，不是沒寫錯誤處理。
問題是它吐出來的字是 **「HTTP 524」**，而且 toast 3 秒就消失。

**所以要修的不是「補一個 catch」，是「提示等於沒提示」。** 三件事：
① 訊息看不懂；② 提示一閃即逝；③ 結果欄留著舊圖誤導人。

## 二、要改的三處

### ① `_apiError()` 要把狀態碼翻成人話（`app.js:2156`）

現在：
```js
function _apiError(data, status) {
    const detail = data && data.detail;
    if (typeof detail === "string") return detail;
    return "HTTP " + status;
}
```

**後端有給 `detail` 就照用，這條保留**——那是後端刻意寫給人看的訊息，不要蓋掉。
只有 fallback 那條要改：沒有 `detail` 時（524 這種被中間層攔掉的就沒有），
依狀態碼給看得懂的中文**加上可行動的建議**。至少涵蓋：

| 狀態 | 訊息方向 |
|---|---|
| 408／504／**524** | 新聞太長，消化超過時間上限。**建議縮短新聞內容，或把字數拉桿降一階再試** |
| 502／503 | AI 服務暫時忙碌或無回應，請稍後再試 |
| 429 | 請求太頻繁，請稍等一下再試 |
| 401／403 | 登入可能已過期，請重新整理頁面後再登入 |
| 其他 | 生成失敗（HTTP <status>），請稍後再試 |

措辭自己斟酌，但**每一條都要讓使用者知道「下一步該做什麼」**，不要只說失敗。
狀態碼可以保留在句尾括號裡（回報問題時有用），但不能是唯一的內容。

### ② 錯誤要留在畫面上，不能用 toast

`showToast` 是 3 秒淡出（`app.js:3598`）。失敗訊息必須**留到使用者自己關掉**。

作法：在一鍵生成結果區塊上方加一個錯誤橫幅（紅底、一個 ✕ 關閉鈕），
`handleOneClickGenerate` 的 catch 改成寫進這個橫幅（toast 要不要同時保留隨你）。
成功時要把橫幅清掉。HTML 結構加在 `index.html`，維持現有 Tailwind 風格。

### ③ 失敗時不要沉默留著上一張舊圖

現在失敗後 `oneClickResult` 原封不動，使用者以為那是這次的結果。
改成失敗時**明確標示那是上一次的成品**（例如在圖上方加一行灰字「⚠ 這是上一次的結果，本次生成失敗」），
或直接把結果區收起來。**兩種都可以，但不能什麼都不做。**
